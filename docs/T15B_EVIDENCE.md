# Compare customer identity before and after protection

Open **Assess assistant → Review defense checks → Run banking checks**. Under **Who chooses the customer?**, inspect the selected assistant and the defended copy. Each button opens that run's actual events. Use **Back to assessment** to return.

The original tool exposes an identity argument. The registered defense binds identity to the signed-in customer on a separate configuration. This observation establishes a permission difference. Showing private data entering a model or reaching a person requires separate runtime evidence.

Expand a banking question to compare answers. Each input comparison carries two receipts, one from each run. Trusted code checks the required question and probe names, each run's outcome, and receipt ownership. Repeating a passing check or borrowing another question's receipts cannot establish a pass. Incomplete evidence yields an inconclusive comparison. Existing saved reports retain their historical verdict.

The JSON download contains the same saved results. This assessment uses a fixture model, real local tools and synthetic records.
