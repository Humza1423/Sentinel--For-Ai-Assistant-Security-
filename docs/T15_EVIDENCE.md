# T15 · Follow a registered defense from finding to verification

Start at **Assess assistant → Run banking checks**. Read the observed capability, likely cause and reviewed defense. Verification reports how many permission and ordinary-use checks passed and how many execution comparisons matched. Expand a banking question to see both answers. Send either run to the inspector to read the recorded model, permission and data events. Download the JSON to retain the underlying report.

The browser test ran in fixture mode with the synthetic bank. It reported four permission checks passed, five banking checks passed and five input comparisons matched. The test opened the latest-transfer pair and confirmed the defended capability event in the inspector. UI tests also verify that missing source evidence remains inconclusive.

The UI uses the persisted verdict from the backend. It reports a verified registered configuration for the checks it ran. Observed disclosure, model-based investigation and generated source patches each require their own evidence.
